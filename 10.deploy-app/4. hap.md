# HPA Notes

HPA = HorizontalPodAutoscaler. Adds/removes pod replicas automatically
based on metrics. File: `k8s/hpa.yaml`

---

## Requirement (one-time kind setup)

HPA needs metrics. Install metrics-server:

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl patch deployment metrics-server -n kube-system --type=json \
  -p='[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--kubelet-insecure-tls"}]'
# (the patch is kind-specific: self-signed kubelet certs)

# verify — this MUST work before HPA does anything
kubectl top pods
```

The deployment MUST also declare cpu requests (in deployment.yaml):

```yaml
resources:
  requests:
    cpu: 100m # HPA % is calculated against THIS, not a full core
```

No requests → CPU-based HPA silently never scales.

---

## The HPA config

```yaml
spec:
  scaleTargetRef:
    name: express-deploy # what to scale
  minReplicas: 3
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 60 # scale up when avg CPU > 60% of requests
```

Meaning: avg CPU across pods > 60% of 100m (i.e. > 60m) → add replicas.
Below it → remove replicas. Never outside 3..10.

## Test it

Terminal 1 — generate load:

```bash
kubectl run load-generator --rm -it --image=busybox:1.36 --restart=Never -- /bin/sh -c "while true; do wget -q -O- http://express-svc:4010/ >/dev/null; done"
```

Terminal 2 — watch:

```bash
kubectl get hpa express-hpa -w
```

Replicas climb 3 → up as CPU crosses 60%. Ctrl+C the generator, and
replicas drop back after ~5 min (stabilization window).

## Commands

```bash
kubectl get hpa                       # status + targets
kubectl describe hpa express-hpa      # events, conditions, recommendations
kubectl top pods                      # actual per-pod CPU/mem
```

## How it decides

Every 15s the HPA controller:

1. Fetches avg CPU per pod from metrics-server
2. desired = ceil(currentReplicas × currentUsage / target)
   e.g. 3 pods at 90% target 60% → ceil(3 × 90/60) = 5 replicas
3. Applies scale-up immediately; scale-down waits 5 min
   (stabilizationWindowSeconds — prevents flapping)

HPA only edits spec.replicas on the Deployment — nothing else.

---

## Gotchas

- While an HPA targets a deployment, DON'T set replicas in
  deployment.yaml — HPA fights it (k8s prints a warning on apply)
- `kubectl top` shows actual usage; HPA % is relative to requests,
  so requests must be realistic (too low = scales too early)
- Scaling up is fast, scaling down is intentionally slow
- HPA ≠ load balancer: the Service already spreads traffic to all
  replicas; HPA just changes the replica count
